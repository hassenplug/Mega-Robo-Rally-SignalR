**Created 2026-11-04. Planning window: Nov 2026 – Nov 2027.** A living tracker, not a plan that
has been executed. **Every date, price, and deadline below is blank or marked "verify" on purpose** —

## How to use this file
1. Add candidate events to the **Event pipeline** table (one row each).
2. Move an event's **Status** forward as you decide. Keep rejected rows — the *Why* saves re-researching next year.
3. When you commit to an event, copy the **Per-event checklist** into its own section under "Event notes".
4. After every event, add to **Lessons log**. That is the most valuable part of this file.

Status values: `idea` → `researching` → `applying` → `accepted` / `rejected` / `waitlisted` → `attended` / `skipped`

### MadCon 26 — Fort Wayne, IN (attended)
- **Outcome:** Players loved the game.
- **Problem:** Router trouble. **Player phones could not connect to the Pi.** The Pi → robots link worked, and the user's computer (a different device) could connect to the Pi.
- **Workaround:** Players used the Pi's own screen and the user's computer screen instead of their phones.
- **Player devices:** phones (not the ESP32 stations).
- **Cause: not yet determined.** What the symptoms do and don't show: the router/Pi/robot side was working, and at least one non-phone client could reach the Pi, so the failure is specific to the phones' path. Candidates to test (none confirmed): phones joined a different network than the Pi (e.g. venue WiFi or a cached SSID), phones on a band/SSID the Pi isn't on, client/AP isolation on the router, phones treating the no-internet network as unusable and switching to mobile data, DNS/hostname (`mrobopi`) not resolving on phones, or a stale seat-cookie/page cache. The computer working suggests the server itself was reachable.
- **Router used at MadCon:** the TP-Link TL-WR802N (confirmed by the user), not the UniFi.
- **Follow-up (2026-11-04):** The user tested with the new UniFi router and phones "seem to work fine." Since MadCon used the TP-Link, the router is the likely cause, but this isn't proven: one home test doesn't reproduce a venue's WiFi interference. Not yet recorded: test conditions (Android/iOS, uplink connected or not, number of phones) and whether it's been tried in a crowded-WiFi environment.
- **Not recorded yet:** dates, cost, table size/power, setup and teardown time, number of players, which phones (Android/iOS), robot issues.
